- `src/pique_py/static/visualizer.css`: navy `#102d4f`, sky `#58a7d8`,
  pale rail `#e3ebf2`, blue-gray headings `#eaf1f6`, restrained panel borders,

## ML_Lab implementation

- One downstream, locally versioned CSS layer applies the same style tokens
  to all five primary tools, their three Data children, forms and data grids.
- `ml_lab_tables.js` now provides one uniform grid for DOM-backed tables:
  global/column search, filtering, sorting, paging, copy and visible CSV.
  The existing server-paged source table and scientific dependency matrices
  retain their separate execution semantics but share the same grid look.
- The sidebar preflight reads the existing per-project experiment SQLite and
  discovers bounded project-local derived outputs. The active dataset's existing SQLite feature-profile cache is checked
  for a reusable summary; recent recorded training/generation runs are listed
  without re-executing them. No source scan, profiling, model training or
  extraction is started merely by opening ML_Lab.
- Small saved datasets are source/provenance verified before receiving a
  *ready* state. Large saved tables are presented as *found* and verified by
  the existing explicit activation-preview route, avoiding unbounded initial
  data rereads. Changed datasets are flagged stale and never suggested as
  immediately reusable. Old derived files without a saved experiment are
  offered only as selections to verify, not silently activated.
- The current instance's verified dataset remains authoritative. Other
  experiment revisions are not implicitly promoted into the active context.
- Server returns mounted URLs generated by Flask; no hard-coded root paths.
- No migrations, new scientific engines, new dependencies or cross-project
  data sharing.

## Boundaries and runtime acceptance

1. The patch should be applied **after ML-UW-25**. Live checkout differences
   may still require reconciliation.
2. Check standalone and PAH-mounted UI `/` -> Data; reload each of the five
   tabs, including a new browser session. Verify existing data is detected and
   can be re-used without re-running the producer.
3. Check the same table appearance and interactions for: tabular inventory,
   source grid (server pagination), XML tables, feature statistics, comparison
   tables, training runs, and selected dataset editors.
4. Validate an invalid/tampered dataset is never silently activated. Large
   files are not fully verified until the user opens the reuse preview.
5. Check dropdowns, scientific matrices, keyboard navigation, file exports,
   and unusual large tables in a real browser. Headless tests do not replace
   PAH-mounted Flask/browser acceptance.
