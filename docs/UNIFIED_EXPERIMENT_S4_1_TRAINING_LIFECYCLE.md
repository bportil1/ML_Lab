# Sprint 4.1 — Configured model execution, state, and artifacts

**Status:** Implemented in ML_Lab only. No PAH, HSQA_DBN, or pyPIQUE changes.

## Purpose

Consume a saved S3.1/S3.2 model specification and S2.1/S2.3 pinned data
selection as **one recorded experiment run**. Reuse the existing ML_Lab model
engines and local store; do not duplicate algorithms, inject arbitrary file
paths, or require the PAH process.

## Headless interface

- `queue_configured_run(store, experiment_id, revision=None,
  expected_revision=None, seed=None)` queues a run. When
  `expected_revision` is supplied, the current revision comparison is performed
  inside the SQLite write transaction.
- `execute_configured_run(store, run_id, progress=None)` claims a queued run
  and executes it **synchronously**. It rejects a second worker claiming the
  same run; exceptions are persisted in `runs.status=failed`.
- `run_configured_experiment(store, experiment_id, revision=None, seed=None,
  progress=None)` combines those steps synchronously.
- `get_configured_run_status(store, run_id)` returns the SQLite run, artifacts,
  and the last best-effort stage snapshot.
- `ConfiguredRunError.run_id` identifies a recorded failed invocation.

The executor calls `prepare_configured_model_handoff` and then the existing
`ml_lab.application.execute_task(task, payload)`. No model family is
reimplemented here; method-specific defaults, training loop behavior, and
random-state options continue to come from their existing scientific engines.
The optional run-level `seed` is **provenance only**; it does not reseed models.

## Project-local outputs

```
<project>/analysis/ml_lab/experiments.sqlite3
<project>/analysis/ml_lab/training_runs/<run_id>/
  input.json       # dataset reference, immutable model spec, and run metadata
  progress.json    # coarse stage snapshot (not an authoritative job state)
  result.json      # existing execute_task response envelope, strict JSON
```

The original CSV/TSV is not copied or overwritten. The source and Data Lab
provenance sidecar (when supplied) are rechecked and registered as immutable
input artifact references. Manifest and result artifacts retain SHA-256 hashes,
revision associations and source links in S1.2's artifact registry. A source
changed before or during execution causes a failed run, not a silent rebind.
No arbitrary checkpoint destination can be configured by users in S4.1.

## Optional UI

The first-party Blueprint adds a **Run configured model** action to the saved
model workspace, the `/experiments/runs/<run_id>` status page, a JSON polling
endpoint, and verified JSON result access. It launches daemon threads with a
small per-Blueprint active-run limit, like the preexisting Data Lab profile job
UI. Running a model does not require or change PAH's private storage.

**Limitations:**

- The worker is in-process. A server restart can interrupt it; SQLite may still
  say `queued` or `running`. There is no restart detection/requeue in S4.1.
- Stage status is **not an epoch counter, throughput estimate, or progress
  percentage**. Models without callbacks expose only preparation, executing,
  persistence, and terminal states.
- Cancellation, durable resume, checkpoint scheduling, optimizer trials and
  per-epoch metric streams are deferred to S4.2 or later work.
- The result JSON may be large for methods that return generated samples; this
  patch records the existing envelope instead of creating a new result format.
- Existing CLI and legacy JSON workbenches continue to operate unchanged.

## Reproducibility / safety expectations

1. Run IDs are generated by the project-local store, and cannot be used to
   access another project's files or results.
2. UI launch binds the **current expected revision** atomically. Headless
   callers may deliberately select a historical revision.
3. Source data and its provenance must still match recorded hashes when results
   are committed; no silent dataset refresh is permitted.
4. A failed run retains its error and any already registered artifacts, but no
   unfinished computation is represented as a successful result.
5. Experiment and run metadata stay in the ML_Lab SQLite catalog. No schema
   upgrade is needed for this sprint.

## Verification

Focused S4.1 tests cover actual PCA execution, input/result checksums,
revision compare-and-swap, stale and concurrently changed sources, failed
scientific engines, duplicate worker claims, cross-project access, symlinked
output paths and the optional in-process worker. UI route tests require the
optional Flask dependency, which must be tested in a Flask-enabled environment.
